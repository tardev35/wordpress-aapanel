กว่าจะวางไฟล์และสร้างผู้ใช้ได้ และกฎแต่ละข้อของเราตัดขั้นไหนทิ้ง**

> มันจะโดนเจาะของจริงภายในไม่กี่ชั่วโมง (bbc29pro.com โดนตอนอายุ 6 วัน) แล้วกลาย

## รันดูเอง

ต้องมี 2 เทอร์มินัล — เทอร์มินัลแรกเปิดเป้า เทอร์มินัลที่สองยิง

```bash
# เทอร์มินัล 1 — เปิดเป้าจำลอง (ไม่มีการป้องกัน)
python tools/attack-lab/target.py

# เทอร์มินัล 2 — เดินลำดับการเจาะ
python tools/attack-lab/attacker.py
```

แล้วเปิดเป้าใหม่ในโหมดเปิดกฎป้องกัน แล้วยิงซ้ำ จะเห็นว่าตัดขั้นไหนทิ้ง:

```bash
# เทอร์มินัล 1 — คราวนี้เปิดกฎ hardening ชุดเดียวกับที่ deploy จริง
python tools/attack-lab/target.py --hardened

# เทอร์มินัล 2 — ยิงชุดเดิม
python tools/attack-lab/attacker.py
```

> เป้าเป็น **WordPress ปลอม** ไม่มีการรันโค้ดจริง เว็บเชลล์ที่ "อัปโหลด" เป็นไฟล์เปล่า
> ทุกอย่างอยู่ในแรม ปิดโปรแกรมแล้วหายหมด `attacker.py` ยิงได้แค่ `127.0.0.1`
> เป็นเครื่องมือฝึก ไม่ใช่อาวุธ

## 6 ขั้นที่บอทเดิน

ลำดับนี้ไม่ได้คิดเอง — ถอดจากสิ่งที่เกิดจริงบน bbc29pro.com เมื่อ 2026-08-29
แต่ละขั้น**ต้องอาศัยขั้นก่อนหน้า** ตัดขั้นไหนได้ ที่เหลือก็ไปต่อไม่ได้

| # | ขั้น | เครื่องมือจริงที่บอทใช้ | สิ่งที่ได้ |
|---|------|----------------------|-----------|
| 1 | ลาดตระเวน | `wpscan`, `curl` อ่าน `<meta generator>` / `readme.html` | รู้เวอร์ชัน → เปิดตารางช่องโหว่ตรงรุ่น |
| 2 | หาชื่อผู้ใช้ | `GET /wp-json/wp/v2/users`, `GET /?author=1` | ได้ชื่อผู้ใช้ = ครึ่งหนึ่งของรหัสฟรี |
| 3 | เดารหัสผ่าน | `wpscan --passwords`, `xmlrpc system.multicall` | ได้บัญชี admin |
| 4 | วางเว็บเชลล์ | อัป `.php` ผ่านช่องโหว่ปลั๊กอิน/ธีม | มีไฟล์รันคำสั่งบนเครื่อง |
| 5 | รันคำสั่ง | เรียกเว็บเชลล์ `?cmd=id` | คุมเครื่องในสิทธิ์ `www` |
| 6 | ฝังตัว | สร้างผู้ใช้ admin สำรอง / วาง cron | กลับเข้ามาได้แม้เปลี่ยนรหัส |

## แต่ละขั้น กฎไหนของเราตัดทิ้ง

### ขั้น 1 — ลาดตระเวน

บอทเปิดหน้าแรกอ่าน `<meta name="generator" content="WordPress 6.4.2">` แล้วลองโหลด
ไฟล์ที่มักหลุด — `readme.html`, `wp-config.php.bak`, `.env`

**กฎที่ตัด** [wp-hardening.conf](../configs/wp-hardening.conf) ข้อ 5 — บล็อก `readme.html`,
`license.txt`, และนามสกุลสำรอง `.bak .env .sql .old`
→ เหลือแค่ meta generator ที่ยังรั่ว (แก้ที่ฝั่ง WordPress ด้วย mu-plugin — ดู [ค้างอยู่](#ยังค้างอยู่))

### ขั้น 2 — หาชื่อผู้ใช้ ⭐ จุดตัดที่คุ้มที่สุด

WordPress เปิด `GET /wp-json/wp/v2/users` ให้ใครก็ได้ดึงรายชื่อผู้ใช้โดยไม่ต้องล็อกอิน
และ `GET /?author=1` จะ redirect ไป `/author/<ชื่อจริง>/`

ทดสอบจริงบน neda88-pro.com ได้ชื่อ `admin` กลับมาเลย

**กฎที่ตัด** [wp-hardening.conf](../configs/wp-hardening.conf) ข้อ 6 — `/wp-json/wp/v*/users` → 401
และ `/?author=` → 403 (REST API ตัวอื่นยังใช้ได้ปกติ)
→ **การเดารหัสต้องมี 2 อย่าง: ชื่อ + รหัส ถ้าปิดชื่อ งานของบอทเหลือครึ่งเดียว**

### ขั้น 3 — เดารหัสผ่าน

สองทางพร้อมกัน:
- `POST /wp-login.php` ยิงรหัสทีละตัว
- `POST /xmlrpc.php` ด้วย `system.multicall` — ยัด **500 การเดาใน request เดียว**
  ยิงหมื่นรหัส/นาทีได้ และทุก POST ข้าม FastCGI cache ไปรัน WordPress เต็มรูป

xmlrpc คือตัวที่ทำ **CPU 92% / load 3.5** บน bbc29pro.com — 15,217 POST ใน 1 ชั่วโมง

**กฎที่ตัด**
- xmlrpc ปิดตายใน [common-site.conf](../configs/common-site.conf) → บรูตแบบขยายกำลังหมดทาง CPU ไม่ถูกเผา
- [wp-hardening.conf](../configs/wp-hardening.conf) ข้อ 7 — `wp-login.php` จำกัด **5 req/นาที ต่อ IP**
  (burst 3) คนพิมพ์รหัสผิดไม่กระทบ บอทยิงรัวโดนเต็ม ๆ

### ขั้น 4 — วางเว็บเชลล์ ⭐ จุดตัดสุดท้ายที่กันความเสียหาย

ต่อให้บอทได้รหัส admin มา มันจะอัปไฟล์ `.php` ผ่านช่องโหว่ปลั๊กอิน/ธีม แล้ววางลง
`wp-content/uploads/` หรือซ่อนใน `wp-includes/x9d5285/`, `uploads/.well-known/.<hash>/`

**กฎที่ตัด** [wp-hardening.conf](../configs/wp-hardening.conf)
- ข้อ 2 — ห้ามรัน `.php` ใน `uploads/` → อัปได้แต่ **เรียกให้รันไม่ได้**
- ข้อ 3 — ห้ามเรียก `.php` ใน `wp-includes/` ตรง ๆ
- ข้อ 4 — บล็อกโฟลเดอร์ซ่อน `/.` (ยกเว้น `acme-challenge`)
→ **ไฟล์ที่วางได้ เอาไปรันต่อไม่ได้ = ยึดเครื่องไม่ได้** ความเสียหายจบที่ตรงนี้

### ขั้น 5–6 — รันคำสั่ง + ฝังตัว

ถ้าขั้น 4 ผ่าน บอทเรียกเว็บเชลล์ `?cmd=id` เพื่อยืนยันว่าคุมเครื่องได้ แล้วสร้าง
ผู้ใช้ admin สำรอง (เช่น `hacker_bkp`) หรือวาง cron ไว้ — ต่อให้เปลี่ยนรหัส admin เดิม
เขาก็กลับเข้ามาได้

**ในโหมด hardened บอทไปไม่ถึงขั้นนี้** เพราะตกขบวนตั้งแต่ขั้น 4

## ผลที่ควรเห็น

| | ไม่มีการป้องกัน | เปิดกฎ hardening |
|---|---|---|
| ขั้น 1 ลาดตระเวน | รู้เวอร์ชัน + อ่านไฟล์สำรองได้ | รู้แค่ meta generator |
| ขั้น 2 หาชื่อผู้ใช้ | ได้ `admin` | **401 / 403 — ตัน** |
| ขั้น 3 เดารหัส | xmlrpc รับ 500/ครั้ง | **xmlrpc ปิด + login จำกัด 5/นาที** |
| ขั้น 4 วางเว็บเชลล์ | อัปแล้วรันได้ | **อัปได้แต่รันไม่ได้ — ตัน** |
| ขั้น 5–6 คุมเครื่อง | **ยึดสำเร็จ** | **ไปไม่ถึง** |

จุดตัดที่คุ้มที่สุด 2 จุด: **ขั้น 2** (ปิดชื่อผู้ใช้ ทำให้บรูตยากขึ้นเท่าตัว) และ
**ขั้น 4** (ห้ามรัน PHP ใน uploads ทำให้ยึดเครื่องไม่ได้แม้รหัสหลุด)

## ยังค้างอยู่

กฎพวกนี้ทำให้ช่องที่เจาะได้**เอาไปใช้ต่อไม่ได้** แต่ไม่ได้แทนสองอย่างนี้:

1. **อัปเดตปลั๊กอิน/ธีม** — ต้นทางของขั้น 4 ยังคือช่องโหว่ในโค้ด กฎแค่กันผลลัพธ์
2. **meta generator ยังรั่วเวอร์ชัน** (ขั้น 1) — ต้องปิดที่ฝั่ง WordPress ด้วย mu-plugin
   `remove_action('wp_head','wp_generator')` nginx ปิดให้ไม่ได้เพราะมันอยู่ใน HTML ที่ PHP สร้าง
