# 13 — ทดสอบช่องโหว่บนโดเมนจริงแบบปลอดภัย

อยากเทสต์การเจาะ (เช่นปลด xmlrpc ดู CPU พุ่ง) บนโดเมนจริงที่จดมาเพื่อทดสอบ
โดยเฉพาะ เช่น `test-qweda.xyz` — ทำได้ แต่มีกฎเหล็กข้อเดียว:

> 🔴 **ปลดเกราะได้ ต่อเมื่อล็อกเว็บให้เข้าได้แค่ IP ของคุณเท่านั้น**

## ทำไมต้องล็อก IP

เราพิสูจน์มาแล้วใน [11-security.md](11-security.md) ว่าบอทหาเว็บใหม่เจอจาก
Certificate Transparency **ภายในไม่กี่นาที**ที่ออก cert (godbet-88.com โดนสแกน
ตั้งแต่อายุ 3 วัน, bbc29pro.com ถูกเจาะตอน 6 วัน)

พอจด `test-qweda.xyz` แล้วขอ SSL → ชื่อโดเมนไหลเข้า CT ทันที → บอทเห็น → ถ้า
xmlrpc เปิดโล่ง บอทจริงจะเข้ามายิงเองในชั่วโมงแรก เว็บทดสอบจะ:
- ถูกยึดเป็นของจริง กลายเป็นฐานยิง/แจกมัลแวร์ไปหาคนอื่น
- โดน xmlrpc ยิงจนเครื่องล่ม (กระทบเว็บอื่นบนเครื่องเดียวกันถ้ามี)

**ล็อก IP แล้วจบ** — คุณยิงเทสต์ได้เต็มที่เพราะมาจาก IP คุณ แต่บอทข้างนอกเจอ
403 ทุกตัว เว็บปลดเกราะได้โดยไม่มีใครนอกจากคุณแตะถึง

## ขั้นตอน

### 1. จดโดเมน + สร้างเว็บบนเครื่องทดสอบ

ใช้ **เครื่องเปล่า** (เช่น 72.62.127.10) ที่ไม่มีเว็บลูกค้าจริง
สร้างไซต์ + ติดตั้ง WordPress ตามปกติผ่าน aaPanel
ชี้ A record ของ `test-qweda.xyz` มาที่ IP เครื่องนั้น

### 2. หา IP ของคุณ

```bash
# รันบนเครื่องคุณ
curl -s https://api.ipify.org; echo
```

ถ้า IP บ้านเปลี่ยนบ่อย (ส่วนใหญ่เป็น dynamic) เผื่อทั้งวงได้ เช่น `1.2.3.0/24`

### 3. ล็อกเว็บให้เข้าได้แค่ IP คุณ

```bash
# รันบนเครื่องทดสอบ
bash tools/attack-lab/testsite-guard.sh test-qweda.xyz lock 1.2.3.4
```

สคริปต์จะใส่ `allow 1.2.3.4; deny all;` ให้ไซต์ แล้วตรวจให้ว่าคนอื่นโดน 403 จริง

### 4. ตรวจว่าล็อกได้ผลก่อนปลดเกราะ

```bash
bash tools/attack-lab/testsite-guard.sh test-qweda.xyz status
```

ต้องขึ้น **ล็อกแล้ว** และ **คนนอกเข้าไม่ได้** ทั้งคู่ ถึงจะไปขั้นต่อไป

### 5. ปลดเกราะ xmlrpc (เฉพาะตอนล็อกแล้ว)

บนเครื่องเปล่าที่เพิ่งลง WordPress ใหม่ xmlrpc **เปิดอยู่แล้วโดยปริยาย** (ยังไม่ได้
deploy [harden-wp.sh](../scripts/harden-wp.sh)) จึงไม่ต้องปลดอะไร — แค่**อย่าเพิ่ง
deploy hardening** ลงไซต์นี้

ถ้าเคย deploy ไปแล้ว ถอดออกชั่วคราวด้วย:
```bash
bash tools/attack-lab/testsite-guard.sh test-qweda.xyz open-xmlrpc
# สคริปต์จะปฏิเสธถ้ายังไม่ได้ล็อก IP
```

### 6. ยิงเทสต์จากเครื่องคุณ

```bash
# ยิง xmlrpc แบบ multicall (ขยายกำลัง) ดู CPU ในหน้า aapanel ของเครื่องทดสอบ
bash tools/attack-lab/xmlrpc-load.sh https://test-qweda.xyz/ 20 30
```

สคริปต์จะตรวจก่อนว่าปลายทางเป็น xmlrpc ของ WordPress จริง แล้ว **ให้พิมพ์ชื่อโดเมน
ยืนยันเอง** กันชี้ผิดเป้า (ถ้าเจอ 403 แปลว่า xmlrpc ยังปิดหรือ IP lock บล็อกเรา —
ต้อง `open-xmlrpc` และเช็คว่า IP เราอยู่ใน allow ก่อน)

CPU จะพุ่งเพราะทุก POST ข้ามแคชไปรัน WordPress เต็มรูป + multicall ยัด 500 sub-call
ต่อ request (ขยายกำลังเท่าของจริง) — ดู [12-attack-simulation.md](12-attack-simulation.md) ขั้น 3

> เครื่องมือนี้ยัด **รหัสหลอกตัวเดียวซ้ำ ๆ ไม่ใช่ wordlist** — WordPress ยังวิ่ง path
> ตรวจรหัสเต็มทุก sub-call จึงเห็น CPU พุ่งเท่าของจริง แต่มัน**เดารหัสใครไม่ได้** (ไม่แปร
> ค่ารหัส ไม่รายงานว่าตัวไหนถูก) เป็นตัววัดภาระ ไม่ใช่ตัวบรูตรหัส

### 7. เก็บกวาด

```bash
bash tools/attack-lab/testsite-guard.sh test-qweda.xyz close-xmlrpc   # คืนเกราะ
# หรือลบไซต์ทดสอบทิ้งเลยผ่าน aaPanel
```

**อย่าลืม** ถ้าจะเลิกล็อก IP (`unlock`) ต้อง `close-xmlrpc` ก่อนเสมอ —
สคริปต์กันไว้ให้แล้วว่าจะไม่ยอมปลดล็อกตอน xmlrpc ยังเปิด

## กฎเหล็ก 3 ข้อ

1. **xmlrpc เปิด → IP ต้องล็อก** ตลอดเวลา ไม่มีข้อยกเว้น
2. **ทดสอบบนเครื่องเปล่า** ที่ไม่มีเว็บลูกค้าจริงร่วมเครื่อง
3. **ลบไซต์ทดสอบทิ้ง**เมื่อเสร็จ อย่าปล่อยเว็บปลดเกราะค้างไว้แม้จะล็อก IP
