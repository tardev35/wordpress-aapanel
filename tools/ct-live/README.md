# ct-live — ดูสตรีม Certificate Transparency สด ๆ ผ่านหน้าเว็บ

หน้านี้คือ [scripts/watch-ct.sh](../../scripts/watch-ct.sh) เวอร์ชันหน้าเว็บ
ทำไว้ให้เห็นภาพว่า **บอทหาโดเมนที่เพิ่งจดใหม่เจอได้จากที่ไหน** — ดู [docs/11-security.md](../../docs/11-security.md)

## รัน

```bash
python tools/ct-live/server.py      # เปิด http://localhost:8765
```

ใช้แค่ python มาตรฐาน ไม่ต้อง pip install อะไร

## เมนู

| เมนู | ทำอะไร |
|---|---|
| สตรีมสด | ดึงใบรับรองล่าสุดจากทุก CT log แยกแท็บตาม log |
| ล็อกที่ใช้ได้ | รายชื่อ log ที่ยังรับ cert อยู่ตอนนี้ |
| เฉพาะโดเมนของเรา | กรองเฉพาะโดเมนใน `/www/wwwroot` (ใช้ได้เมื่อรันบนเซิร์ฟเวอร์) |
| คัดกรองเว็บพนัน | ส่งชื่อโดเมนให้ AI ช่วยดูว่าตัวไหนน่าจะเป็นเว็บพนัน |

## เปิดใช้ตัวคัดกรอง AI

```bash
cp tools/ct-live/.env.example tools/ct-live/.env
# แก้ .env ใส่คีย์จาก https://openrouter.ai/keys
```

รัน server ใหม่ แล้วเข้าเมนู **คัดกรองเว็บพนัน**

ส่งไปแค่ **ชื่อโดเมน** ไม่ได้เปิดเว็บ ไม่ได้ส่งอย่างอื่น
รุ่นเริ่มต้น `google/gemini-3.1-flash-lite` — 45 โดเมนใช้ราว 850 token เข้า

⚠️ โมเดลดูจากชื่ออย่างเดียว **ผิดได้ทั้งสองทาง** เว็บทั่วไปที่มีตัวเลขอาจโดนทำเครื่องหมาย
และเว็บพนันที่ตั้งชื่อธรรมดาจะรอด ใช้จัดลำดับว่าควรดูตัวไหนก่อน ไม่ใช่คำตัดสิน

## proxy (ไม่บังคับ)

ใส่บรรทัดละตัวใน `tools/ct-live/proxies.txt` — ไฟล์นี้ถูก gitignore ไว้ มีรหัสผ่าน

```
host:port@user:pass
```

แยกเป็น **2 ไฟล์ คนละงาน** เพราะปลายทางคนละแบบ:

| ไฟล์ | ใช้กับ | ควรใช้ IP |
|---|---|---|
| `proxies.txt` | RDAP เช็ควันจดโดเมน | ที่ไหนก็ได้ |
| `proxies-probe.txt` | เปิดหน้าเว็บอ่าน `lang` | **ต่างประเทศ** |

RDAP ต้องกระจายหลาย IP เพราะทะเบียนจำกัดคำขอต่อ IP หนัก
ส่วนการเปิดหน้าเว็บจะลอง proxy ก่อน ล้มเหลวแล้วยิงตรงเสมอ

### ⚠️ คุณภาพต่างกันมากระหว่างผู้ให้บริการ

วัด 2026-08-30 ด้วย **IP ไทยทั้งคู่ จาก ISP ชุดเดียวกัน** (3BB, True, AIS, CAT)
ยิงเว็บพนันไทยชุดเดียวกัน:

| ผู้ให้บริการ | เว็บพนันไทย | เว็บทั่วไป (ตัวควบคุม) |
|---|---|---|
| bestproxy | **3/18** | ผ่าน |
| webshare | **28/30** | 20/20 |
| ยิงตรง | 6/6 | ผ่าน |

รูปแบบไฟล์ต่างกัน รองรับทั้งคู่:

```
host:port@user:pass     bestproxy
host:port:user:pass     webshare
```

### บันทึกความผิดพลาด

ตอนแรกสรุปว่า **"ISP ไทยบล็อกเว็บพนัน"** เพราะเห็น TLS ถูกตัดที่ **5.2 วินาทีเป๊ะ
ทุกครั้ง** ซึ่งเป็นลายเซ็นของการตัดโดยเจตนา ไม่ใช่เว็บล่ม

พอเปลี่ยนไปใช้ webshare ที่เป็น IP ไทยจาก ISP ชุดเดียวกัน **กลับผ่านหมด**
แปลว่าตัวที่ตัดคือ**เครือข่ายของ bestproxy เอง** ไม่ใช่ ISP ไทย ข้อสรุปเดิมผิด

> **บทเรียน** อาการที่สม่ำเสมอเกินไปบอกว่า *มีคนตั้งใจตัด* แต่ไม่ได้บอกว่า
> *ใครตัด* ต้องเปลี่ยนตัวแปรทีละตัวถึงจะรู้ — ที่นี่คือเปลี่ยนผู้ให้บริการ
> โดยคุมประเทศและ ISP ไว้เหมือนเดิม

ลองตัวใหม่ก็ผ่าน)
